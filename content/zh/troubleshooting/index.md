# 故障排查

## 工作流无法保存

先查看编辑器定位到的节点和字段。旧节点、不支持的字段、无效资源引用或错误连线会阻止保存，但当前修改会
继续保留。修正后重试，不要通过反复退出编辑器绕过检查。

错误消息包含“操作 ID”时请一并记录；它用于在日志中关联同一次失败。

## 自动化目标违反契约或未就绪

- 确认节点选择的是当前电脑已配置的目标槽位。
- 确认目标程序、Android 设备或浏览器调试页面仍在运行。
- Windows 目标应检查标题、窗口类和多窗口选择策略。
- 从其他人导入工作流后，应在本机重新绑定目标，不要依赖对方机器的程序身份。

## 快捷键没有响应

- 检查快捷键设置中是否存在冲突或注册失败。
- 启动器 `1–9` 快捷键只在启动器可见且开关启用时生效。
- 启动器隐藏后会主动释放槽位快捷键。
- 某些系统或游戏保留组合键，需要更换组合。

## 点击位置偏移

- 确认目标窗口客户区分辨率和录制时一致。
- 检查坐标使用的是屏幕绝对位置、窗口相对位置还是比例位置。
- 回放相对鼠标轨迹前确认当前目标使用正确的 360° 校准档。

## 关闭 Yotta 时等待较久

Yotta 关闭前会停止当前操作、恢复需要丢弃的编辑草稿并释放运行时、快捷键和窗口资源。关闭 Modal 会显示
当前阶段；资源释放有超时保护。不要在处理中反复启动另一个 Yotta 实例。

## AI 看不到我刚修改的节点

先保存工作流。AI 提案读取已保存版本；MCP 的 `authoring_context` 会报告当前编辑器是否有未保存修改。

## 无法取得默认目标截图

确认工作流设置了默认目标并保存。检查本机是否有对应目标、窗口是否打开、设备是否连接。需要其他目标时可明确提供目标标识。

## 截图成功，但模型说看不到图片

确认使用支持图片的模型，外部 MCP 客户端也需要把图片内容传给模型。不要把工具结果手动复制成仅包含 JSON 的文本。

## AI 生成的位置不准确

重新获取当前画面，核对窗口是否移动、缩放或切换页面。确认使用目标坐标还是屏幕坐标，并按截图元数据处理缩放。详见[截图与坐标](../screenshots.md)。

## MCP 连接不上

保持 Yotta 运行，在 MCP 设置中确认服务已启用，客户端端口与设置一致。检查是否有其他程序占用了端口。

## 提案没有直接执行

提案用于审查修改。接受后检查工作流，再主动运行；截图与编译检查不会自动执行鼠标或键盘操作。
